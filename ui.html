Operator screens, the notifications page and Telegram messages

The main user is the operator, who watches peat pixels, reads why a pixel is AWAS (MAUT attributes with their measured numbers, and neighbours), reads the agent's verification, then publishes or rejects. Published messages reach the web inbox and Telegram DMs of that province's subscribers, who press Confirm receipt. The web app already runs in the team repo ktp-asapify-fe in mock mode (fictional data, demo sign-in) or live mode (Google sign-in); in live mode all data comes through the API. Default language is English, with an EN/ID switch in the top bar that the device remembers.

02 · Flows

Three flows that must run smoothly in the demo

Operator
Message in the operator group→Open the cluster detail→Read MAUT parameters + neighbours→Read verification + images→Publish / reject

There is no level to choose. Clusters without a decision stay monitored.

Archive night
Open the calendar in the slot player→Pick a date with a dot→Play that night's 54 slots→Open that night's cluster

The map, cluster outlines and list follow the chosen night.

Subscriber
Pick provinces + channels, consent→Operator publishes→Telegram DM + inbox→Confirm receipt

One message per channel per event. Accepted by the provider does not mean read.

Rules

  • Caption at most 1,024 characters; numbers come from clusters and verifications, never retyped
  • Never says "confirmed fire"; the last line reads "AWAS status comes from satellite rules; it is not a field confirmation"
  • The caption stays in Indonesian (its recipients are responders in Indonesia), also when the web screen is in English; the demo video uses English subtitles
  • The bot only accepts /start <code> through the webhook to link an account and never replies; it stores only the chat_id of subscribers who linked themselves. HTML tags are stripped for DMs

08 · Language and copy

One language per screen

Rules

  • English by default; EN/ID in the top bar, remembered per device. en.json and id.json must hold the same keys
  • Agent text follows the screen language (finding/finding_en, summary_id/summary_en); errors are written from code
  • AWAS stays AWAS in both languages as the status name (the English version explains it once: Indonesian for "beware")
  • Alert message text (inbox, Telegram DM) stays in Indonesian
  • Plain, active sentences: no jargon, no em dashes

09 · Stack

A light frontend, also for low-end phones

Build
React 19 + Vite + TypeScript (team repo ktp-asapify-fe)
Map
MapLibre GL JS 6; the module worker is served as-is from /maplibre/
Motion
motion (springs), lazy-loaded; off under reduced motion and in lite mode
Charts
hand-written SVG for UtilityChart and the parameter table
Type
IBM Plex through @fontsource (no Google Fonts)
Mode
VITE_API_MODE=mock (default, fictional data + demo sign-in) or live (VITE_API_BASE, VITE_PEAT_LAYER_URL, VITE_PROVINCES_LAYER_URL)
Auth
demo sign-in in mock mode; Firebase JS SDK (Auth, Google sign-in) in live mode. The role = operator claim opens the map and decisions; other accounts get /notifikasi only
Push
Firebase Messaging + the notification-sw.js service worker, exercises/non-emergency only; it also keeps the inbox for offline reading when the user opts in
Hosting
Firebase Hosting, /api/** to Cloud Run asapify-api (the judged prototype URL). A mock-mode preview on Vercel serves internal review
Lite mode
automatic when data saver is on, RAM ≤ 2 GB, the CPU is limited, or reduced motion is set: plain basemap, no glow/grid lines/camera animation, pixel ratio 1
