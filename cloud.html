Bangun image, deploy dua servicebash
gcloud artifacts repositories create asapify --repository-format=docker --location=$REGION
gcloud builds submit --tag $IMAGE .                  # ulangi setiap ada perubahan kode

# 1) asapify-agent: privat, hanya bisa dipanggil sa-jobs dan sa-api
gcloud run deploy asapify-agent --image $IMAGE --region $REGION \
  --command uvicorn --args=agent.main:app,--host,0.0.0.0,--port,8080 \
  --service-account $AGENT_SA --no-allow-unauthenticated \
  --cpu 1 --memory 2Gi --concurrency 4 --min-instances 0 --max-instances 3 --timeout 300 \
  --set-env-vars "GOOGLE_CLOUD_PROJECT=$PROJECT_ID,GOOGLE_CLOUD_LOCATION=$GEMINI_LOCATION,\
GOOGLE_GENAI_USE_VERTEXAI=True,GEMINI_MODEL=$GEMINI_MODEL,DATA_BUCKET=$DATA_BUCKET" \
  --set-secrets FIRMS_MAP_KEY=firms-map-key:latest,TELEGRAM_BOT_TOKEN=telegram-bot-token:latest
for SA in $JOBS_SA $API_SA; do
  gcloud run services add-iam-policy-binding asapify-agent --region $REGION \
    --member "serviceAccount:$SA" --role roles/run.invoker; done
AGENT_URL=$(gcloud run services describe asapify-agent --region $REGION --format='value(status.url)')

# 2) asapify-api: publik untuk web; endpoint operator dijaga token Firebase di kode
gcloud run deploy asapify-api --image $IMAGE --region $REGION \
  --command uvicorn --args=api.main:app,--host,0.0.0.0,--port,8080 \
  --service-account $API_SA --allow-unauthenticated \
  --cpu 1 --memory 1Gi --concurrency 40 --min-instances 0 --max-instances 3 --timeout 60 \
  --set-env-vars "GOOGLE_CLOUD_PROJECT=$PROJECT_ID,DATA_BUCKET=$DATA_BUCKET,AGENT_URL=$AGENT_URL" \
  --set-secrets TELEGRAM_BOT_TOKEN=telegram-bot-token:latest

⚠️ Bila gcloud builds submit gagal karena izin service account Cloud Build di project baru, beri akun build roles/artifactregistry.writer dan roles/logging.logWriter, lalu ulangi. ⚠️ Bila requirements.lock dari Mac/Windows gagal dipasang di Linux, buat ulang lock di Cloud Shell. Hari penjurian: --min-instances 1 untuk kedua service.

10 · Job dan Scheduler

Lima job, empat jadwal, semuanya dari image yang sama

Deploy job dan jadwalbash
ENV="GOOGLE_CLOUD_PROJECT=$PROJECT_ID,DATA_BUCKET=$DATA_BUCKET,PUBLIC_BUCKET=$PUBLIC_BUCKET,BBOX=$BBOX,AGENT_URL=$AGENT_URL"
COMMON="--image $IMAGE --region $REGION --service-account $JOBS_SA --command python --set-env-vars $ENV"

gcloud run jobs deploy asapify-ingest-himawari $COMMON --args=-m,jobs.ingest,--sat,himawari \
  --cpu 2 --memory 4Gi --task-timeout 8m --max-retries 0
gcloud run jobs deploy asapify-ingest-gk2a     $COMMON --args=-m,jobs.ingest,--sat,gk2a \
  --cpu 2 --memory 4Gi --task-timeout 8m --max-retries 0
gcloud run jobs deploy asapify-evaluate        $COMMON --args=-m,jobs.evaluate \
  --cpu 2 --memory 4Gi --task-timeout 8m --max-retries 0
gcloud run jobs deploy asapify-environment     $COMMON --args=-m,jobs.environment \
  --cpu 2 --memory 4Gi --task-timeout 30m --max-retries 1
gcloud run jobs deploy asapify-build           $COMMON --args=-m,jobs.build_all \
  --cpu 2 --memory 8Gi --task-timeout 60m --max-retries 0

for JOB in "asapify-ingest-himawari|*/10 20-23,0-4 * * *" \
           "asapify-ingest-gk2a|*/10 20-23,0-4 * * *" \
           "asapify-evaluate|5-59/10 20-23,0-4 * * *" \
           "asapify-environment|0 12 * * *"; do
  NAME="${JOB%%|*}"; CRON="${JOB#*|}"
  gcloud scheduler jobs create http "$NAME-schedule" --location $REGION \
    --schedule "$CRON" --time-zone "Asia/Jakarta" \
    --uri "https://run.googleapis.com/v2/projects/$PROJECT_ID/locations/$REGION/jobs/$NAME:run" \
    --http-method POST --oauth-service-account-email $SCHED_SA
done

# sekali setelah deploy
gcloud run jobs execute asapify-build --region $REGION --wait

# replay satu slot (AS_OF menggantikan waktu sekarang)
gcloud run jobs execute asapify-ingest-gk2a --region $REGION --wait \
  --update-env-vars AS_OF=2023-09-25T15:00:00Z

# backfill paralel: 8 task, tiap task mengambil tanggal dengan CLOUD_RUN_TASK_INDEX
gcloud run jobs execute asapify-ingest-gk2a --region $REGION --tasks 8 --task-timeout 6h \
  --args=-m,jobs.backfill,--sat,gk2a,--start,$BACKTEST_START,--end,$BACKTEST_END,--step,10,--night-only

Jadwal 20-23,0-4 WIB mencakup 20.00–04.50; slot setelah 04.00 WIB (21.00 UTC) diabaikan kode. Ingest dan evaluate tanpa retry karena siklus berikutnya 10 menit lagi dan semuanya idempoten per slot. Evaluate berjalan 5 menit setelah ingest supaya file kedua satelit sempat tertulis.

import sys, firebase_admin
from firebase_admin import auth
firebase_admin.initialize_app()
email, role = sys.argv[1], sys.argv[2]   # operator

    auth.get_user_by_email(email).uid, {"role": role})

14 · Urutan deploy

Dari project kosong sampai jadwal berjalan

  1. Project, billing, env.sh, aktifkan API, daftar Earth Engine (Runbook S0-2, S0-3).
  2. Service account dan peran (03), akses secret (04).
  3. Bucket dan Firestore (05). Pindahkan tg_chats ke Firestore.
  4. Bangun image, deploy asapify-agent lalu asapify-api (09); cek /api/v1/health.
  5. Deploy lima job (10); jalankan asapify-build sekali.
  6. Backfill Himawari dan GK2A (Agustus – 15 Okt 2023), lalu asapify-environment --as-of per hari jendela backtest.
  7. Replay evaluate untuk jendela backtest; cek kelompok muncul di Firestore.
  8. Buat empat jadwal Scheduler.
  9. Deploy web, aktifkan Auth, set akun operator demo.
  10. Pasang monitoring dan budget alert.
